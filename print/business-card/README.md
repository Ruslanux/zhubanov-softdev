# Визитка Zhubanov SoftDev — как она собирается

Визитка 90×50 мм, двусторонняя (4+4), в фирменном стиле сайта. Файл для типографии собирается
одной командой из HTML-шаблона: CMYK, текст в кривых, вылеты и линия реза, QR-код чистым чёрным.

```bash
python3 print/business-card/build.py
```

## Файлы

| Путь | Что это |
| --- | --- |
| `card.template.html` | вёрстка обеих сторон с полями `{{NAME}}`, `{{PHONE}}` и т. д. |
| `build.py` | данные визитки (словарь `CARD`) и весь конвейер сборки |
| `out/vizitka_90x50_4+4_CMYK.pdf` | **файл для печати**: стр. 1 — лицо, стр. 2 — оборот |
| `out/ТЗ_для_типографии.txt` | требования к печати и рекомендации по бумаге — отдаётся вместе с PDF |
| `out/preview.png` | как визитка выглядит после резки |
| `out/preview_guides.png` | с вылетами: красная линия — рез, зелёная — безопасная зона |
| `out/card.html` | вёрстка с подставленными данными — открыть в браузере для правок |

Нужны: `google-chrome`, `gs` (Ghostscript), `pdfinfo`/`pdftoppm` (poppler-utils),
Python-модули `qrcode` и `Pillow`.

Чтобы поменять данные (должность, телефон, адрес QR), правьте `CARD` и `QR_URL` в `build.py`
и запускайте сборку заново. Папка `print/` исключена из сборки сайта (`exclude` в `_config.yml`).

## Общая схема

```
данные (имя, телефон…) ─┐
QR-код (матрица)       ─┼─► HTML/CSS-шаблон ─► Chrome (PDF в RGB) ─► Ghostscript ─► PDF для типографии
                         │                                             (CMYK, кривые, линия реза, QR в K100)
                         └─► проверки: размер, шрифты, краски, QR ─► превью PNG + ТЗ
```

## Шаг 0. Требования типографии

| Требование | Значение | Зачем |
| --- | --- | --- |
| Формат | 90×50 мм (стандарт в СНГ; европейский — 85×55) | размер после резки |
| Вылеты | +2 мм с каждой стороны → страница 94×54 мм | нож режет с погрешностью, фон должен заходить за край |
| Безопасная зона | текст не ближе 3–5 мм к линии реза | чтобы нож не задел текст |
| Цвет | CMYK, а не RGB | печатные машины работают четырьмя красками |
| Шрифты | в кривых (контурах) | у типографии может не быть ваших шрифтов |
| Сумма красок (TAC) | не больше ~300 % | иначе краска не высыхает и мажется |
| Прозрачность | лучше без неё | старые системы вывода её плохо обрабатывают |
| Мелкие чёрные элементы | только K100, не смесь четырёх красок | при смеси краски чуть смещаются, и край «двоится» |

## Шаг 1. Данные и QR-код

Тексты — в словаре `CARD`. QR-код строит библиотека `qrcode`: она выдаёт матрицу из True/False,
а не картинку.

```python
qr = qrcode.QRCode(error_correction=qrcode.constants.ERROR_CORRECT_M, border=0)
qr.add_data("https://zhubanov-softdev.dev/")
qr.make(fit=True)
matrix = qr.get_matrix()   # 29×29 из True/False
```

Матрица нужна, чтобы нарисовать каждый модуль векторным прямоугольником: растровая картинка
QR при печати размывается.

## Шаг 2. Вёрстка в HTML/CSS в миллиметрах

CSS понимает `mm` и `pt`, поэтому визитка верстается как веб-страница:

```css
@page { size: 96mm 56mm; margin: 0; }            /* лист с запасом — см. шаг 4 */
.page { position: absolute; left: 1mm; top: 1mm;
        width: 94mm; height: 54mm; }              /* визитка + вылеты */
.back h1 { font-size: 12.5pt; }                   /* кегль в пунктах, как в полиграфии */
.contacts li { font-size: 7.1pt; }                /* минимум для печати — 6 pt */
```

Правила:

- Все элементы позиционируются в мм от края страницы: `left: 7mm` — это 5 мм от линии реза.
- Только непрозрачные цвета: никаких `rgba()`, `opacity` и полупрозрачных теней. «Свечение» —
  градиент между сплошными цветами.
- Иконки — встроенный SVG, чтобы остались векторными.
- Класс `guides` на `<body>` рисует линию реза и безопасную зону — только для превью.

## Шаг 3. HTML → PDF через headless Chrome

```bash
google-chrome --headless=new --no-sandbox --disable-gpu \
  --no-pdf-header-footer --virtual-time-budget=8000 \
  --print-to-pdf=print-rgb.pdf file:///путь/card.html
```

`--virtual-time-budget` даёт время загрузиться веб-шрифтам. На выходе векторный PDF, но цвета
в нём RGB, а шрифты встроены как шрифты.

## Шаг 4. Ловушка: Chrome округляет формат страницы

Заданные 94×54 мм Chrome выводит как 93,81×54,02 мм — округляет по своей сетке, и через CSS
(мм, pt, px, дюймы) точный размер не получить.

Решение: Chrome печатает лист 96×56 мм, визитка лежит внутри со сдвигом 1 мм, а Ghostscript на
следующем шаге вырезает ровно 94×54. Вертикальный сдвиг `build.py` вычисляет по фактической
высоте страницы из `pdfinfo`.

## Шаг 5. Ghostscript: CMYK, кривые, точный размер, линия реза, QR

```bash
gs -q -dBATCH -dNOPAUSE -dSAFER -sDEVICE=pdfwrite \
   -dCompatibilityLevel=1.6 -dPDFSETTINGS=/prepress \
   -dNoOutputFonts \
   -sColorConversionStrategy=CMYK -dProcessColorModel=/DeviceCMYK \
   -dDEVICEWIDTHPOINTS=266.457 -dDEVICEHEIGHTPOINTS=153.071 -dFIXEDMEDIA \
   -sOutputFile=vizitka.pdf setup.ps -f print-rgb.pdf
```

- `-dNoOutputFonts` — весь текст в кривые.
- `-sColorConversionStrategy=CMYK` — RGB → CMYK по ICC-профилю, с генерацией чёрной краски.
- `-dDEVICEWIDTHPOINTS/…HEIGHTPOINTS` + `-dFIXEDMEDIA` — точный размер страницы
  (1 мм = 72/25,4 ≈ 2,8346 pt, 94 мм = 266,457 pt).
- `setup.ps` — программа на PostScript, её генерирует `build.py`:

```postscript
%!PS
globaldict /zsPage 0 put                          % свой счётчик страниц
<<
  /BeginPage {                                    % в начале каждой страницы:
    pop
    [/TrimBox [5.669 5.669 260.787 147.402]       %   линия реза (2 мм = 5,669 pt от края)
     /BleedBox [0 0 266.457 153.071] /PAGE pdfmark
    -2.835 -3.214 translate                       %   сдвиг листа: визитка встаёт точно в 94×54
  }
  /EndPage {                                      % в конце страницы:
    exch pop 0 eq dup {
      globaldict /zsPage get 1 eq {               %   только на обороте (вторая страница)
        gsave initmatrix 0 0 0 1 setcmykcolor     %   чистый K100
        188.787 127.559 1.843 0.668 rectfill      %   …по прямоугольнику на серию модулей QR
        grestore
      } if
      globaldict /zsPage globaldict /zsPage get 1 add put
    } if
  }
>> setpagedevice
```

QR рисуется здесь, а не в HTML, по такой причине. Любой чёрный из RGB после перевода в CMYK
становится смесью четырёх красок (примерно C75 M68 Y67 K90). А `0 0 0 1 setcmykcolor` задаёт
цвет сразу в CMYK, и он проходит в файл без изменений. В HTML на месте QR — пустая белая подложка.

### Ошибки, на которых легко споткнуться

1. **`-dUseFastColor`** (упрощённый перевод) не генерирует чёрную краску: чёрный превращается
   в C100 M100 Y100 K0. Для печати недопустимо — только перевод по ICC.
2. **TrimBox через `/PAGES pdfmark`** молча игнорируется. Работает `/PAGE pdfmark` внутри `BeginPage`.
3. **EndPage обязан возвращать `true`/`false`** — печатать страницу или нет. Если возвращать
   `true` всегда, на выходе получаются пустые страницы.
4. **Счётчик страниц.** Системный `count` в EndPage всегда 0: PDF-интерпретатор перед каждой
   страницей заново инициализирует устройство. Счётчик в `userdict` тоже не работает: страница
   выполняется внутри `save/restore`, и restore откатывает изменения. Нужен `globaldict`.
5. **Шрифты Type 3.** Chrome встраивает вариативные шрифты Google как Type 3 — отсюда
   предупреждения `Bad bounding box in Type 3 glyph` при растеризации промежуточного PDF.
   В финальном файле шрифтов нет вовсе (`-dNoOutputFonts`), так что это не проблема.

## Шаг 6. Проверки — как это сделал бы препресс

```bash
pdfinfo -box vizitka.pdf      # размер 266.46×153.07 pt и TrimBox 5.67…260.79
pdffonts vizitka.pdf          # пустой список = весь текст в кривых
strings vizitka.pdf | grep -oE "/Device(RGB|CMYK)|/SMask"   # только CMYK, без прозрачности
gs -o p%d.tif -sDEVICE=tiff32nc -r300 vizitka.pdf           # растр CMYK для замеров
```

- **Сумма красок**: растр CMYK открывается в Pillow, сумма каналов пикселя = TAC.
  Сейчас максимум 291 %.
- **QR в K100**: в зоне QR допустимы только пиксели 0/0/0/100.
- **Сканируемость**: рендер оборота (`pdftoppm -r 300` и `-r 120`) распознаётся декодером
  `jsQR` (Node.js) и ведёт на сайт.

## Шаг 7. Превью и передача в типографию

- `pdftoppm -r 300 -png` рендерит страницы в PNG.
- Pillow обрезает вылеты, скругляет углы, добавляет тень и ставит стороны рядом (`preview.png`).
- Отдельно — версия с линиями реза и безопасной зоны (`preview_guides.png`).
- В типографию уходят `vizitka_90x50_4+4_CMYK.pdf` и `ТЗ_для_типографии.txt`.

Ограничение: цвета переведены стандартным профилем Ghostscript. Для точного попадания в цвет
возьмите у типографии её ICC-профиль (часто ISO Coated v2 / FOGRA39) и добавьте в команду
`-sOutputICCProfile=профиль.icc`.

## Если делать программу или сайт по созданию визиток

**Архитектура на Rails 8:**

1. **Шаблоны** — HTML/ERB или Phlex с полями и координатами в мм, как `card.template.html`.
   В базе — шаблон, поля, форматы (90×50, 85×55), размер вылетов.
2. **Редактор** — форма и живое превью на Hotwire: тот же HTML в браузере с включёнными
   линиями реза.
3. **Валидация до печати** — текст не выходит за безопасную зону, кегль не меньше 6 pt,
   контрастность, длина полей.
4. **Генерация PDF** — фоновая задача Solid Queue: Chrome (гем `ferrum` / `grover` или
   Playwright) → Ghostscript той же командой → результат в Active Storage.
5. **Автоматический preflight** — проверки из шага 6 в коде: размер, TrimBox, нет шрифтов
   и RGB, сумма красок, QR декодируется. Не прошёл — заказ не уходит в печать.
6. **Дальше** — QR с vCard (контакт сразу в телефон), несколько языков, PDF/X-1a
   (у Ghostscript есть режим `-dPDFX`), заказ и оплата, интеграция с типографиями.

**Альтернатива Chrome.** PDF можно собирать сразу в CMYK библиотекой — в Ruby это Prawn: CMYK-цвета
и миллиметры напрямую, без перевода RGB→CMYK и обрезки листа. Но вёрстку придётся писать кодом,
а не HTML/CSS. Для визуальных шаблонов удобнее HTML, для строгого контроля печати — Prawn.

**Лицензии:**

- Ghostscript распространяется по AGPL. Для коммерческого SaaS проверьте условия или купите
  коммерческую лицензию у Artifex.
- Шрифты Google Fonts (лицензия OFL) можно встраивать и переводить в кривые без ограничений.
